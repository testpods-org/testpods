TestPods · JUnit 5 Extension

Lifecycle Reference

A step-by-step walkthrough of how @TestPods bootstraps, provisions, and tears down Kubernetes pods during a test run.

Startup
1

Extension Registration

@TestPods is meta-annotated with @ExtendWith(TestPodsExtension.class), so JUnit automatically wires in the extension for any test class that carries the annotation.

2

beforeAll — Primary Startup Path

The extension's beforeAll() method orchestrates the full startup sequence:

  • Reads the test class and its @TestPods annotation.
  • Calls populateAndValidateRegistry(testClass).
  • Attaches the registry to the Provisioner.
  • Calls provisioner.provisionTestPods().
  • Injects the resolved cluster and started pods into static fields (and non-static fields if an instance already exists).
TestPodsExtension.java:46
3

Registry Population via Reflection

populateAndValidateRegistry() scans the test class and any declared provider classes:

  • Locates a static @RegisterCluster field on the test class.
  • Scans static null @TestPod fields — these are injection targets.
  • Scans static initialized @TestPod fields — these are startup sources.
  • Applies the profile lifecycle policy from @RegisterCluster or falls back to @TestPods(deleteProfileAfterTests = …).
  • Instantiates each class listed in @TestPods(testpodsProviders = …).
  • Scans provider classes for their own @TestPod and @RegisterCluster fields.
Initialized @TestPod fields are startup sources. Null @TestPod fields are injection targets — an important distinction.
TestPodsExtension.java:211
Provisioning
4

Ensuring an Active Cluster & Namespace

Provisioner.provisionTestPods() delegates to Registry.provisionTestPods(), which first calls ensureNamespaceIsActive():

  • If no cluster was explicitly registered, calls K8sCluster.discover(profileLifecyclePolicy).
  • Discovery builds the default MinikubeCluster, then falls back to the minikube profile.
  • The cluster is stored in TestPodDefaults as a thread-local supplier.
  • A default namespace is created if the cluster has none, then stored as the shared namespace for this test thread.
Registry.java:66–73
5

Minikube Startup (if Needed)

When discovery creates a fresh MinikubeCluster, its constructor:

  • Runs preflight checks.
  • Checks the profile status — attaches if already running, starts it with cli.up(…) if stopped or absent.
  • Creates and pings a Kubernetes client.
  • Creates a fresh TestPods namespace.
  • Starts the dashboard proxy on a best-effort basis.
MinikubeCluster.java:67
6

Topological Ordering

Before any pod is started, the registry orders all initialized pod fields using topological sort based on property references.

If pod B references a property owned by pod A, pod A is started first. Circular dependencies throw an IllegalStateException.

Registry.java:133
7

Starting Each Pod

For each ordered FieldInitialization, the registry:

  • Verifies the field value is a Pod.
  • Registers it by annotation/field pod name, and also by pod.getName() if set.
  • Injects the cluster into the pod (if not already set).
  • Gives the pod the shared PropertyContext.
  • Calls pod.start(), then pod.publishProperties(propertyContext).
  • Tracks it in startedPods.
Registry.java:92
8

Resolving Runtime Defaults in pod.start()

For managed pods, BaseManagedPod.start() is final and performs these steps in order:

  • Resolves cluster and namespace defaults.
  • Runs preStart() if the pod implements PodLifecycleHooks.
  • Calls doStart().
  • Runs postStart() if present.

Namespace resolution priority: explicit namespace object → explicit namespace name → shared namespace from TestPodDefaults → cluster default namespace → newly created namespace.

BaseManagedPod.java:740, 839
9

Creating Kubernetes Resources

doStart() does the actual Kubernetes work:

  • Adds the pod's internal port to exposed ports.
  • Creates a workload manager (e.g. Deployment or StatefulSet).
  • Creates the service manager.
  • Builds the Kubernetes PodSpec.
  • Creates the workload resource and the service resource.
  • Waits for readiness.
  • Logs debug deployment details if debug logging is enabled.
On any failure, partial resources are cleaned up and a TestPodStartException is thrown.
BaseManagedPod.java:763
10

Readiness Wait

The active wait strategy is either user-configured via waitingFor(…) or the pod type's default. Both Deployment and StatefulSet pods default to readiness-probe based waiting.

The strategy polls pod.isReady() until success or timeout — tests do not begin until this gate passes.

BaseManagedPod.java:805 · ReadinessProbeWaitStrategy.java:49
Test Execution
11

Injecting Back into the Test Class

After provisioning, beforeAll() injects:

  • The resolved K8sCluster into any static K8sCluster fields.
  • Started pods into static null @TestPod fields, matched by resolved pod name.
  • Non-static cluster and pod fields if a test instance is available.

postProcessTestInstance() also runs the same non-static injection path, covering normal JUnit test-instance creation timing.

TestPodsExtension.java:55, 266
12

Test Methods Execute

beforeEach() and afterEach() are currently no-ops. All meaningful startup work is class-level, so tests run against already-running pods without per-test overhead.

Teardown
13

afterAll — Cleanup

When @TestPods(deleteNamespaceAfterTests = true):

  • Calls registry.tearDown().
  • Stops started pods in reverse startup order.
  • Deletes all registered owned namespaces.
  • Closes the cluster — may stop or destroy the TestPods-owned Minikube profile depending on the lifecycle policy.
  • Clears TestPodDefaults thread-local state.
If deleteNamespaceAfterTests = false, the namespace, pods, and cluster are left running for inspection.
